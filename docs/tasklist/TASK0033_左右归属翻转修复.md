# TASK0033 左右归属翻转修复（检测器标签按假设对待）

- 状态：已完成 · 2026-11-25
- 产出：`tools/pose_repair.py`（新模块）、`tools/extract_motion.py`（去噪后接入）、`tools/upgrade_motion.py`（存量动作文件原地修复 + 重算深度）

1. 问题：MediaPipe 的左右归属逐帧独立假设，转身/遮脸时整段标反（BUG0051）—— 且上半身可以单独反。这是**几何性错误**：肩肘腕接到对面的肩上，手臂画到身体另一侧，3D 判据（穿模/弯折侧向）全部失真。
2. 判据：真翻转 ⇔ 画面上左右互换 ⇔ 时间连续性强烈冲突（左手的轨迹接上右手上一帧的位置）。真实运动没有这种「轨迹交换」。
3. 实现：上半身（肩/肘/腕）、下半身（髋/膝/踝）各一组共享翻转状态；2 态 Viterbi（状态 = 该帧该组是否互换）取时间最平滑解。翻转代价**按帧**计（λ = 0.25 × 该组对间距中位）：短 glitch（1-2 帧）修得起，长段落（真实转身时的连续交换）修不起 → 不误伤转身。
4. 接入：新提取在 `denoise_poses` 之后、通道推导之前；存量文件由 `upgrade_motion.py` 修复（幂等：已平滑的序列不会再翻）并重算 pose3d。
5. 边界实测（文档化）：换 `--pose-model full` 重提取 —— 左右翻转 0 帧（比 lite 好），但深度时域更抖（p95 90→102mm、max 279→395mm），运行时穿模收敛在 t=7.21/14 恶化到 57/42mm（E18 fail）。结论：**lite + 翻转修复是当前最优组合**；full 的优势（零翻转）已被修复步骤覆盖，劣势（抖动）没有。工具保留 `--pose-model {lite,full,heavy}` 供以后复测。

- 验收：A1~A5 全过；E7 在 t=3.08 的违例消除；E14 4.1%、E16 3.8% 不变
