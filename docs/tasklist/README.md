# Tasklist 管理机制

## 编号

`TASKNNNN`，NNNN 从 0001 起单调递增，不复用、不重排。文件名 `TASKNNNN_简述.md`，简述用中文短语，路径分隔符 `/` 写成 `·`。

## 何时写

**每实装 1 个 task 就写 1 篇**，与代码同一次提交。判据是「可独立验收的能力单元」，不是「一次会话」「一次提交」。

不写 task 的：纯重构、纯文案、依赖升级、被更大 task 吸收的子步骤。

## 状态

| 值 | 含义 |
|---|---|
| 进行中 | 已开工未验收 |
| 已完成 | 已实装且验收断言通过 |
| 已废止 | 方案被证伪或被更大 task 取代（保留文件，说明原因） |

## 模板

```markdown
# TASKNNNN 标题

- 状态：进行中 · YYYY-MM-DD
- 产出：`路径` · `路径`

1. 关键设计决策（结论，不是过程）
2. …

- 验收：断言名 / 命令
```

要点：只写**结论**（做了什么、为什么这么做、边界在哪），不写推理过程、不写步骤说明、不写版本信息。验收必须可执行或可指认。

## 关联

- 配套的缺陷记录在 `docs/buglist/`，用 `BUGNNNN` 互引。
- 每个 task 至少关联一条验收断言；无断言的 task 不算完成。
