# BUG0051 MediaPipe 把左右归属整段标反（肩肘腕接到对面的肩上）→ 手臂画到身体另一侧

- 状态：已修 · 2026-11-25
- 现象：t=3.08（帧 74）画面上人面朝镜头、左肩在画面右侧，2D 检测却把 left_shoulder 放在画面左（u=−0.105）、right_shoulder 放在画面右（u=+0.181）—— 上半身左右整体互换 2 帧。渲染上左臂装到右肩上：手被深度重构放到胸腔里 → 触发穿模推出 → 弯折侧向反了（E7 违例 0.163m）。t=4.0（帧 97-98）同类再发一次，帧 119-126（人转身到侧向）标签也不稳。
- 根因：MediaPipe 的左右归属是**逐帧独立**的假设 —— 转身、手遮脸、快速甩臂时它会整段标反，而且**上下半身可以独立反**（帧 74 只有上半身反，腿是对的）。
- 判据（可自证）：真翻转 ⇔ 该组关键点在画面上左右互换 ⇒ 时间连续性强烈冲突（横向跳变 ≈ 该对的间距；左手的轨迹接上右手上一帧的位置）。真实运动不会出现这种「轨迹交换」。
- 修法：`tools/pose_repair.py` —— 上半身（肩/肘/腕）、下半身（髋/膝/踝）各一组，2 态 Viterbi（翻转/不翻转）取时间最平滑解；翻转代价**按帧**计（λ=0.25×对间距中位）：短 glitch（1~2 帧）修得起，长段落（真实转身）修不起 → 不误伤。
- 检出的翻转帧：upper 13 帧（74-75, 97-98, 119-126, 161-162）、lower 4 帧（97-98, 161-162）。
- 教训：**检测器的左右标签是一个假设，不是事实** —— 用它之前先问「这帧的标注和上一帧连续吗」。

- 回归：修复后 E7 在 t=3.08 的违例从 0.148m 消除；E14/E16 对齐不变（4.1%/3.8%）；A1~A5 全过
