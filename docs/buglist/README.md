# Buglist 管理机制

## 编号

`BUGNNNN`，NNNN 从 0001 起单调递增，不复用、不重排。文件名 `BUGNNNN_症状短语.md`，症状短语用中文，路径分隔符 `/` 写成 `·`。

## 何时写

**每检测到 1 个 bug 就写 1 篇**，先于修复。判据是「可复现或可指认的缺陷」，包括：数值错误、量纲/单位错误、符号约定错误、竞态与状态污染、验收盲区、性能与资源超限。

不写 bug 的：个人偏好、与代码无关的建议、已在 task 记录里覆盖且无独立症状的观察。

## 状态

| 值 | 含义 |
|---|---|
| 待修 | 已定位根因，未动手 |
| 已修 | 已修且有回归断言 |
| 已规避 | 单目/素材的固有限制，改用其他机制绕开（写清绕开方式） |
| 已废止 | 判定为非缺陷（如验收判据本身写错） |

## 模板

```markdown
# BUGNNNN 症状短语

- 状态：已修 · YYYY-MM-DD
- 现象 / 根因：可观察的症状 + 一句话根因
- 修法：一句话
- 回归：断言名 / 快照
```

要点：**根因必须与现象分开写**。「看起来像」的症状几乎总有别处的根因（如「手臂横成稻草人」的根因是肘的幅度被骨长强制，而不是角度算错）。

## 价值

- 同一类根因反复出现时，先查 buglist 再动手。
- 验收盲区类 bug（断言漏检）要单独标记，它们会让整个验收体系失效。
