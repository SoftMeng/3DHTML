# BUG0037 主体裁剪图宽高比写反 → 模型看到压扁的画面，全部回答 unknown

- 现象：能力基线里「主体裁剪」变体的逐题准确率全为 null（分母 0，全部记 unknown），而「整帧」变体正常。
- 根因：`person_crop` 里缩放高算成了 `crop.shape[1] * width / crop.shape[0]` —— `shape[0]` 是高、`shape[1]` 是宽，公式反了，裁剪图被横向压扁（实测人像被压成宽 512 高 1520 的扭曲条带）。
- 影响：模型对畸形画面只能回答 unknown → 会把「主体裁剪」误判为不可用能力，进而错误地把掌向语义通道排除在管线之外。
- 修法：高 = `crop.shape[0] * width / crop.shape[1]`（宽高比保持）。同批的 `full` 变体与 `verify_vlm.fit` 公式本就正确，无需改。
- 附加修正：探针改为**逐帧落盘**（中途 HTTP 失败不丢已测数据），VLM 客户端的 HTTP 错误信息带状态码与响应片段（原来只报异常类型，定位不到 4xx/5xx）。

- 回归：`tools/probe_vlm.py --n 2` 的裁剪变体不再全 unknown；`docs/constraint/vlm_boundary.md` 的逐题准确率
