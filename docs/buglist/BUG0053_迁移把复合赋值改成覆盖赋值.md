# BUG0053 迁移脚本把复合赋值（`x += v`）改成覆盖赋值（`x = v`）→ 播放推进被重置

- 状态：已修 · 2026-11-25
- 现象：模块化重构后的第一次有界验收 45/47：B3（播放推进）挂（播放 1s 只推进 0.37s）、E18（穿模）在 t=7.21 报 77.5mm。
  而 E18 的**运行时采样真值没变**（仍 15.0mm）⇒ 不是判据变了，是被测的时刻错了。
- 根因：跨模块状态写要经 setter，迁移脚本把 `playhead += dt*speed;` 改写成 `setStatePlayhead(dt*speed);` ——
  **复合赋值读旧值，脚本只抄了右半边** ⇒ 播放头每帧被重置为 `dt*speed`（≈0.04s）⇒ 渲染停在错误的时刻 ⇒
  E18 量到的是另一帧的手部位置（77.5mm 是真实穿模，不是回归）。
- 修法：脚本识别 `+=`/`-=`/`*=` 等复合赋值，改写成 `setStateX(X op v)`（先读旧值再写回）；
  并补一条验收侧的兜底 —— B3（播放推进）本就在 48 条断言里，是它把问题抓出来的。
- 教训：**代码改写脚本本身也要被验收覆盖**。批量改写赋值语句时，复合赋值与多语句同行是最容易漏的两类；
  改写后必须跑一遍行为断言（不能只看「语法通过」——这次语法是通过的）。

- 回归：48/48；B3 播放推进恢复（1s 推进 ≥1s）；E18 网格真值 0.7mm
