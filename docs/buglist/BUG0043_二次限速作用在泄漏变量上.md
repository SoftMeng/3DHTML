# BUG0043 深度重累积后的二次限速作用在泄漏变量 depth[k] 上 → 只有右踝被限速

- 状态：已修 · 2026-11-25

- 现象：右踝的深度与右膝的深度关系与其余骨不一致（踝比膝"浮"着），限速行为左右不对称。
- 根因：重累积循环里写 `arr = depth[k]` —— `k` 是更早的 `for k in keys` 循环残留的变量，值恒为最后一个键 `right_ankle`。于是那段"对绝对深度再限速一次"的代码**只对右踝生效**，其余骨没被限速。
- 修法：删掉这段二次限速。绝对深度的平滑由「根深度 z0 的中值去毛刺 + 每根骨 Δz 的限速」承担（Δz 限速后逐层重累积，绝对深度自然有界）；多一次绝对限速反而会让子骨的深度与父骨脱钩。
- 附带：相机距离 z0 的逐帧毛刺（可见身高占比是逐帧测量，单帧误检造出 0.3m 跳变）改用 5 帧中值去毛刺。

- 回归：A1~A5 全过；A2 深度连续性 95 分位 37~40mm（阈值 60mm）
- 教训：与 BUG0042 同源 —— 循环里的变量名一旦跨作用域复用，编译器不会报错，测试也未必覆盖得到；**每个循环只认自己声明的变量**。
