# Architecture

## 管线

```
原始视频 ──▶ 多模态提取 ──▶ 动作文件（Schema JSON） ──▶ 渲染 3D 行为轨迹 ──▶ 导出视频
             tools/extract_motion.py    示例.motion.json          index.html          webm
             tools/depth_reconstruct.py
             tools/vlm_annotate.py
```

中间产物是**唯一契约**：渲染器只认动作文件，不认视频。换视频只改动作文件，不改渲染层。

## 职责边界（不可越界）

| 层 | 负责 | 不负责 |
|---|---|---|
| 提取层（python） | 像素级检测 → 置信度修复 → 逐帧归一化 → 去噪 → 语义通道 → 深度重构 | 不做渲染决策、不看渲染结果 |
| 重构层（python） | 2D + 透视缩短 → 相机系三维骨架（pose3d） | 不猜不可观测量（深度符号由解剖先验 + 帧间连续性 + **2D 剪影可见性约束**裁决） |
| 语义层（python + 多模态模型） | 掌向/动作语义标注 → `chan.palm` / `chan.semantic` | 只出序关系与粗分类；不产出度量深度 |
| 渲染层（`src/app/*`，产物 index.html） | 骨架映射 → IK → 姿态 → 掌向扭转 → **穿模收敛（网格真值 + 相机射线推出）** → 相机 → 布景 → 导出 | 不重新检测、不重新推断姿态 |
| 几何内核（`src/core/*`） | 射线求交 / 视线穿透区间 / 2 骨 IK 几何 / 弯折面搬运 / 可见手部穿透量 —— 纯函数、零依赖、Node 可单测 | 不碰 DOM / three.js / 全局状态；只吃标量与 Vec3 |
| 验收层（node） | 断言渲染结果与源视频的一致性 | 不参与生产逻辑 |

## 数据契约

- **规格（schema v1）**：`示例.json`。origin = 首帧相机正下方地面点；+x = 相机右；+y = 相机初始朝向；`facing_deg` 从 +x 逆时针（90=背对、270=面向）；`camera.fov_deg` 是**水平** FOV；`framing` = 可见高/画面高。
- **动作文件（v4）**：`示例.motion.json`。`version:4` · `keys`(17) · `poses`(2D，逐帧躯干单位，髋中点原点) · `chan{yaw,roll,root,contact,conf,palm,semantic}` · `videoBox{w,h,K,frac,torsoPx}` · `pose3d`(相机系三维，米) · `pose3dConf` · `pose3dMeta` · `body`。
- **兼容**：v1/v2 必须仍可加载（无 pose3d 时四肢退回 2D 路径；无 `chan.palm` 时掌向用解剖先验）。新增字段只用新名字（`pose3d` 不用 `poses3d`），旧字段标注弃用。

## 坐标系（三套，不可混用）

| 系 | 用途 | 定义 |
|---|---|---|
| 规格系 | 轨迹与机位 | x=相机右，y=相机初始朝向，z=纵深 |
| 相机系 | 深度重构 | x=画面右，y=画面上，z=远离相机（右手系），原点=髋中点 |
| 躯干系 | 驱动骨骼 | +X=自身左，+Y=上，+Z=面朝 |

相机系 → 躯干系：`body_x = cosψ·cam_x + sinψ·cam_z`；`body_y = cam_y`；`body_z = sinψ·cam_x − cosψ·cam_z`（ψ = 躯干转身角）。

## 渲染层内部顺序

规格采样 → 动作采样 → 躯干转身（独立节点，不污染根四元数）→ 躯干侧倾（链式增量）→ 髋高 → 头 → 四肢 IK（接触门控）→ **掌向扭转** → **穿模收敛**（沿相机射线**双向**试推，弯折面随弦搬运；让位绕弦旋转、同侧候选优先；判据用躯干网格真值）→ **掌向补扭** → 相机 → 布景 → 按需绘制。

穿模收敛必须在掌向扭转**之后**：手指朝向决定指尖会不会插进身体；而收敛会重解手臂链、覆写手骨四元数，所以收敛后要补扭一次（扭转幂等）。
收敛的弯折面一律用**随弦搬运的极向量**，不用绝对提示点：弦被推转过之后，绝对提示点里沿弦的分量会泄漏到垂直方向，肘翻到弦的另一侧（反关节）。

## 禁止

- 渲染层内做检测或姿态推断。
- 离线做低通（带滞后，滞后比噪声更伤一致性）。
- 动作文件里出现渲染专用的字段。
- 改规格语义而不同步 README 与示例。
