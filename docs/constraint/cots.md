# Task Workflows

按任务类型选用；非当前类型勿全套执行。详情不足时先提问。

## 通用

澄清目标 → 定位最小改动面 → 实现 → 语法检查 / 离线断言 → 视觉探针 → 有界验收 → 写 tasklist / buglist

## 新能力（feature）

定契约（Schema 字段或断言）→ 定验收判据 → 实现 → 离线断言 → 探针 → 验收 → `docs/tasklist/TASKNNNN_*.md`

## 缺陷（bug）

复现 → 量化症状 → **最小根因**（症状与根因常常不在一处）→ 修 → 回归断言 → `docs/buglist/BUGNNNN_*.md`

## 姿态/算法改动

先做**可观测性判定**（这个量在单目下到底能不能观测）→ 能观测则走观测，不能则走先验+连续性 → 纯计算离线验收 → 再进渲染层

## 换模型

量比例与骨名（`glb_bones.mjs` / `glb_inspect.mjs`）→ 判断命名约定与手指骨 → 评估换装/几何修补链的重做量 → 再决定

## 换视频

重跑提取 → 复核断言阈值（人体比例基线会变）→ 视觉抽查 → 验收

## 文档

只写结论与边界，不写过程与版本信息；与代码同一次提交更新。

## 规则

- 不扩大范围；不臆测需求与接口。
- 阻塞时询问，不硬编。
- 每次实装 task / 发现 bug 都落盘记录（见 docs/tasklist、docs/buglist）。
