# R15 计划：给姿态链路补上「深度」维度

> 目标：让 3D 人偶与源视频逐帧同形同位，消除肢体穿模，并让手掌朝向解剖正确。

## 诊断（已实测，非推断）

| 编号 | 事实 | 证据 |
|---|---|---|
| D1 | **全链路无深度**：四肢末端目标只由 `ax.left`/`ax.up` 构成，无视线轴分量 | `index.html` 手臂/腿 IK 分支；探针导出同帧 `shoulderL.z / handL.z / ankleL.z` 几乎相等（t=0：3.000/3.000/3.017） |
| D2 | **肘的幅度被骨长强制**：`solveChain` 中 `h=√(L1²−a²)`，而 `resolveBend` 只给方向不给幅度 → 肘被甩到肩同高、横向 28 cm → 上臂变水平 | `probe_base_7_21.png` / `probe_base_10.png`（稻草人手臂） |
| D3 | **手腕从未被赋旋转**：掌向是前臂朝向的偶然副产品 | `index.html` 无 `LeftHand/RightHand` 的旋转赋值；`portrait_t7_21.png` 掌面呈平板 |
| D4 | **源 2D 姿态在关键处不可靠**：腕点落在宽袖内、踝点落在阔腿裤脚；肘角在朝镜头弯折时投影塌陷（t=6.5 肘角 174°，实际折叠） | `probe_pose.jpg` 骨架叠加；动作文件逐帧夹角统计 |
| D5 | **MediaPipe Hands 在本片不可靠**：检出 167/192，但尺寸落在解剖合理区间的仅 3/9；观众席满是举手与手机灯 → 大量误检 | `probe_hand_stats.py` 全片统计 |
| D6 | **头发是「布」不是「发」**：开口圆柱 + 背面剔除 → 渲染成带竖纹的平板斗篷 | `portrait_t7_21.png` |
| D7 | 深度重构器可行：单目下每根骨的深度差由透视缩短唯一确定 `\|Δz\|=√(L²−d²)` | 几何恒等式；世界系与图像系同向余弦中位 0.97–0.998（`probe_hand_stats.py`） |

**根因收敛**：D1（缺深度）同时解释「穿模」与「掌向不对」；D2（肘的量纲错误）解释「手臂横成稻草人」。三者同源于「在无深度的屏幕平面上重建三维骨架」。

## 范围

**in**：离线深度重构器 → 动作文件 v3 → 运行时三维目标驱动 → 穿模兜底 → 程序化掌向 → 源姿态质量升级 → 头发几何 → 验收扩展 → 文档

**out**：手指逐节动画（Mixamo 无指骨）；布料/自碰撞模拟；多主体动作提取；换模型（65 骨无发骨，换模型不解决本轮问题）

## 任务

### T0 基线快照与回滚点 ✔ 已完成
`history/R15_baseline/`（index.html、verify.mjs、extract_motion.py、motion_pipeline.py、示例.motion.json、本计划）

### T1 离线深度重构器 `tools/depth_reconstruct.py`（纯计算）
- 产出 `reconstruct(poses, fps, boneLen, priors) -> {pose3d[], quality}`：`pose3d[i][j]` = 第 i 帧第 j 关键点在**视频相机系**的三维坐标（米，髋中点原点，x=画面右 / y=画面上 / z=远离相机）
- 逐骨 `Δz = ±√(L²−d²)`；`d` 用模型骨长为上限、视频比例先验（E15：腿 50.7% / 躯干 27.6% / 头颈 21.7%）为参考；`d>L` 钳位并记录
- 符号裁决：解剖先验（肘偏后 / 膝偏前 / 踝在膝后）作软代价 + 帧间深度连续性作硬代价 → **符号序列 DP**（每帧每骨 2 态），避免逐帧独立判决造成深度闪跳
- 验收（纯 node/python）：① 重投影平均偏差 < 1.5% 画面宽；② 相邻帧关节深度差 95 分位 < 0.06 m；③ 每骨符号翻转 ≤ 1 次；④ ≥70% 帧满足解剖深度先验

### T2 动作文件 v3
- 新字段名 `pose3d`（不带 s），旧 `poses3d` 保留并标注「已弃用、不参与重定向」→ 语义不冲突
- v1/v2 读取路径完全不动
- 验收：v1/v2/v3 三份文件均可被查看器加载且无 JS 异常

### T3 运行时改为三维目标驱动 `index.html`
- `pose3dAt(t)` 采样；**视频相机系 → 躯干系**：绕竖轴旋转 `−(chanYaw + 基准朝向)` + 相机俯仰修正
- 末端目标 = 锚点 + 三维方向 × reach；reach 由**一维搜索**确定，使末端**投影**贴合视频观测点，约束 `|L1−L2| ≤ reach ≤ L1+L2`（腿另受「踩实锁定」约束）
- `solveChain` 改接受**肘/膝的三维目标位置**（来自 `pose3d` 中点），末端固定；旧的 `resolveBend`/`bendObs2D` 保留为 v1/v2 降级路径
- 验收：E14 手部对齐 ≤6%（当前 6.8%）；**E16 脚部对齐 ≤10%**；**E-new 肘膝投影 ≤6%**；时间连续性不劣化

### T4 穿模兜底
- 躯干/头/双腿/两臂的胶囊代理（半径按实测）
- 逐帧算穿透深度；末端沿**视线轴**最小推开（投影不变 → 一致性零代价）；肘/膝沿弦线垂向 ±35° 调整弯折面（终点不动）
- 验收：**E18 最小穿透深度 ≥ −0.005 m**、穿模帧占比 <2%；推开后 E14/E16 劣化 ≤1%

### T5 掌向
- **程序化解剖模型**（主）：基础态掌朝中线+拇指朝前 / 手高于肩→掌朝前 / 双手在胸前（间距<0.35 m）→ 两掌互指 / 前伸>0.4 m→掌朝下。四态按连续权重混合
- 驱动 `LeftHand`/`RightHand`：目标旋转 = 躯干系目标 × 静止姿势逆旋转（用 `rig.initQuat`，不链式累乘）
- **观测增强（辅）**：`tools/extract_hand.py` 上半身大裁剪跑 HandLandmarker，门限＝世界系与图像系同向余弦>0.85 且尺寸在解剖区间；运行时仅在置信足够时以权重 ≤0.5 混合
- 验收：**E17 掌法向与前臂轴夹角 <50°**、相邻帧掌法向夹角 99 分位 ≤40°

### T6 源姿态质量升级 `tools/extract_motion.py`
- 逐帧**裁剪复检**：整帧检测定位人框 → 外扩 25% 裁剪 → 放大到长边 ≥480 px → 复检 → 映射回原帧
- 模型 `pose_landmarker_lite` → `pose_landmarker_full`（已下载 `tools/models/`）
- 糊帧（推镜）检测：躯干像素长变化率 >25% 且置信骤降 → 整帧级邻帧插值 + 链空间重建
- `videoBox.torsoPx`/`frac` 重算
- 验收：**E19 腕点质量**（可检出帧上两法腕距中位 <45 px）；E10/E11 不回归；四帧骨架叠加目视正确

## 风险

| # | 触发 → 后果 | 缓解 |
|---|---|---|
| R1 | `d>L` → 深度无解、钳位为 0 | 用视频比例先验换算参考上限而非硬钳；钳位比例入验收门限 |
| R2 | 朝镜头的骨段投影极短 → Δz 符号在噪声中翻 | DP 的连续性代价压过先验；翻转次数作断言 |

| R5 | MediaPipe `handedness` 在非镜像输入下会翻转 | **不使用 handedness**，改用与 BlazePose 腕点距离指派；断言指派一致率 ≥95% |

## 验证分层

1. **纯 node/python**（秒级，零浏览器）：T1 四条性质、T2 格式兼容、T3 量纲换算、T6 关键点统计 → 每次改代码先跑
2. **视觉探针**（单浏览器实例，一次多时刻）：`node tools/probe_render.mjs --view=match|overlay --times=... --tag=...` → 判断穿模/掌向/稻草人手臂是否消失
3. **有界验收**（每轮仅一次）：`node tools/verify.mjs`（43 断言、≤120 s、结束必 kill）

采样时刻集：`{0, 2.5, 4, 6.5, 7.21, 10, 12.5}`（近景/远景/推镜糊帧/举臂/叉腰/张掌）

**不可观测边界**（勿再尝试）：肢体真实深度（受 R1/R2 限制）、绕竖轴真实扭转、腾空高度、手指逐节姿态

## 已完成的附带修复（2026-11-24）

- **深链启动崩溃**：`setAspect`/`setView` 只作为 `window.__app` 方法存在，`loadSpec` 的深链还原块以自由函数调用 → `ReferenceError: setAspect is not defined`，页面「启动失败」。按既有 `setPlaying` 范式上提到模块作用域，`__app` 改用简写。
- **验收盲区**：B17 导航的正是该深链 URL，但 `waitReady()` 返回值被丢弃、断言只查 `playhead`/`spec`/`url` —— 这三项在抛错点之前已赋值，故「启动失败」照样 PASS。B17 已补 `ready`、错误面板、`aspect`、`view` 四项。
- **探针脚本残留进程**：`.then(()=>process.exit(0))` 会跳过 `.finally` → 清理不执行 → Chrome 残留。已改为 `process.exitCode` + 在 `finally` 内退出。
